# Uris Hall 近与中档：单点 UV 溯源

这里的 A、B 仅是两个确切锁定到模型和原始共享 4096 图集的采样坐标，不是所有单点 UV 的异常豁免。两点占近档 2672/3444、中档 1832/2168；余近档 772、中档 336 面未归类。本次不写网格或贴图。

| 采样点 | 近 / 中三角 | 原可编辑近档 UV 锚面 | FBX 所在真实模型区与烘焙信号 |
|---|---:|---|---|
| A (0.7842459083,0.4465146661) | 1400 / 680 | 3312，中档对应 2124；四角 UV 中心相符，四个顶点均连到被标面 | 模型南侧约 z=0.15–3.90 m，采样 RGB 13/7/3，Mask 红/Alpha=217/140，吻合烘焙 Bronze 的 0.85 金属、0.55 光泽。 |
| B (0.7022064328,0.2104660869) | 1272 / 1152 | 3195；四角 UV 中心相符，四个顶点均连到被标面；中档不再保有同一锚面 | 同侧约 z=5.00–12.80 m（中档 5.60–12.00 m），RGB 约 32/62/50，Mask 红/Alpha=77/102，吻合 Copper 的 0.30 金属、0.40 光泽。 |

两组每个三角的最小正坐标轴投影跨度 ≤0.20 m（仅几何指标，不等于量得构件厚度）。原 `pipeline/bake.py` 177–186 行会把过小 UV 对应面吸附到共顶点有效面 UV 中心，不检查同材质；188–206 行则特意把窄于等效 2.5 px 的特定材料边面转成同材质色样。A、B 锚点都与非退化源四边形中心一致，且颜色、金属和光泽编码支持铜合金边饰，不支持它们源于入口石板的任意回读丢失。尚无逐面的中间烘焙材质索引，不能证明每个面的原始归属，也不能区分两条分支各触发多少次。远景无此两组变更。

两点在基准采样处均为中性编码法线 (128,128,255)、无发光，ControlMask 也一致。A 的基色双线性四像素一致；B 的基色不是常量，不能把任意小的 UV 三角扩展描述为精确等价。不同层级滤波、三角自己的切线空间和游戏内实测仍未验证。先保留已有色样；下一步优先对其余 772/336 面找原有效邻面、区分真实掉图和色样，再决定是否做局部多通道重烘。

尺寸控制补充：纽约市 OTI 点与 BIN 1084473 双重匹配，屋顶属性 132.37 ft（40.346 m）是从最低地面计的父级轮廓属性；城市轮廓大于项目引用的 OSM 轮廓。该数字不是已配准的模型主塔高度，不能据此缩放所有 LOD。参见 [官方记录](https://data.cityofnewyork.us/resource/5zhs-2jue.json?bin=1084473) 和 [轮廓数据释义](https://github.com/CityOfNewYork/nyc-geo-metadata/blob/main/Metadata/Metadata_BuildingFootprints.md)。
